# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

MIPA (MIMIC-IV Phenotyping Atlas): builds phenotyping datasets from the MIMIC-IV / MIMIC-IV-Note dataset and evaluates both classic ML and LLM-based approaches to detecting 16 clinical phenotypes (e.g. `dementia`, `hfref`, `sle`, `vte_past`) from structured EHR data and discharge/radiology notes. There are three independent entry points that share the same preprocessed cohort data but do not otherwise interact:

1. `mimic_parser.py` — turns raw MIMIC-IV into per-phenotype pivoted feature tables (the only producer of `data/processed/`).
2. `supervised_ML.py` — trains classic ML models (LR, RF, GBM, Naive Bayes) on the pivoted output.
3. `llm_evaluation.py` — prompts LLMs directly on discharge summaries/notes and scores them against human-adjudicated labels.

There is no test suite in this repo — verify changes by running the relevant script end-to-end (often against `--debug_type`/`--debug_phenotype` or a small `--phenotypes`/`--models` subset) rather than expecting `pytest` to exist.

## Setup and running things

```sh
# Python 3.11 required
python3.11 -m venv venv-3.11 && source venv-3.11/bin/activate
pip install -r requirements.txt
```

Secrets/config, none of which are checked in:
- `.env` at project root: `OPENROUTER_API_KEY`, `DEEPINFRA_API_KEY`, `LAMBDA_API_KEY` (loaded by `scripts/constants.py` via `dotenv`).
- `secrets/service-account-file.json`: GCS credentials, only needed if a path is a `gs://...` URI (see "Local vs GCS" below).
- MedCAT models under `medcat/medmen/` (`cdb.dat`, `vocab.dat`) — only needed when `--NLP true`.

Build the cohort atlas (writes into `data/processed/cohort/...`):
```sh
python mimic_parser.py --train True                                  # default silver-labeled training set
python mimic_parser.py --train False --noisy_label False             # golden test/val split
python mimic_parser.py --debug_type PROC --debug_phenotype diabetes_type_1   # single phenotype/table, fast iteration
python mimic_parser.py --run_notes_nlp_parsing                       # MedCat NLP pass only
```

Train classic models (reads `data/processed/`, writes `data/models/`):
```sh
python supervised_ML.py
```

Run LLM phenotyping / consistency evaluation (reads `data/filters/golden_notes.csv` + `golden_labels.csv`, writes `output/`):
```sh
python llm_evaluation.py --run_llm_phenotyping --run_entropy
python llm_evaluation.py --run_llm_phenotyping --phenotypes sle --models gemma_7b_it \
  --chunking_methods document naive --prompt_strategies etp --aggregation_methods etp
```
`data/filters/golden_notes.csv` must be generated by hand from `docs/golden_notes.sql` against a licensed MIMIC-IV install; `golden_labels.csv` is checked in.

Full CLI flags for both scripts are documented in `README.md` and `llm_evaluation_README.md` — check those before re-deriving argument semantics from code.

## Architecture

### 1. `mimic_parser.py` pipeline (`scripts/preprocessing/`, `scripts/generation/`, `scripts/featureselection/`)

For each phenotype, four stages run in sequence, each stage's output path derived by `scripts/utils.py` `generate_*_path` helpers from `(phenotype, train, noisy_label, df_type, ...)`:

1. **`generate_raw_csv`** (`scripts/generation/generation.py`) — loads raw MIMIC-IV tables via `scripts/utils.py::load_mimiciv` (Dask, gzip CSVs), builds the baseline cohort (`scripts/preprocessing/cohort.py::generate_baseline_cohort`), applies per-table preprocessing (`scripts/preprocessing/hosp/hosp_preprocess.py`: ICD grouping, NDC/medication grouping, lab/chart/procedure/notes cleanup), and labels admissions. Training labels come from `phenotype_cohort_train` using rule-based **silver labels** (`data/filters/silver_labels.json`, ICD-code lookup); test/val labels come from `phenotype_cohort_test`, which is strictly driven by `data/filters/golden_labels.csv` (human-adjudicated) — silver-label logic is deliberately not used there. `data/filters/test_subject_ids.csv` is always excluded from the training cohort to prevent leakage.
2. **`generate_features_selection`** / **`generate_summary`** (`scripts/featureselection/feature_selection.py`) — per-table, per-phenotype quantile-based feature pruning (`lower_labs`, `lower_chart`, `lower_icd`, `lower_meds`, `lower_nlp` thresholds drop the least-frequent `itemid`/`icd_code`/`ndc`/`cui_code` values) plus optional MedCAT NER over notes (`scripts/featureselection/medcat_parser.py`, UMLS CUI extraction filtered by `TYPE_IDS_FILTER` in `scripts/constants.py`).
3. **`generate_pivot`** (`scripts/featureselection/pivot.py`) — reshapes long-format events into one row per `hadm_id`, either `simple` (count-aggregate per admission) or `timeseries` (count-aggregate per `agg_window`, e.g. daily/hourly bucket).
4. Everything is orchestrated by `mimic_parser.py::main()` (arg-driven) or `main_noarg()` (hardcoded params, branches into a different code path entirely for `train=False` — it batches all phenotypes through the "shared test/validation" path instead of looping per-phenotype).

`PHENOTYPES` (the canonical 16-item list) lives in `scripts/constants.py` and is duplicated inline in several functions (`scripts/preprocessing/cohort.py`, `supervised_ML.py`) — if you add/remove a phenotype, grep for the literal list rather than assuming one source of truth.

### 2. Local vs GCS paths (`scripts/utils.py`, `scripts/constants.py`)

Every `generate_*_path` function in `scripts/utils.py` accepts the same `(phenotype, train, noisy_label, ...)` shape and returns a path string. Constants in `scripts/constants.py` currently point at **local filesystem paths** under `data/` and `output/` (this was migrated off `gs://mipa-bucket/...`, see the commented-out `LOCAL_*` constants and GCS path comments for the original layout). `scripts/utils.py::is_gcs_path`/`setup_gcs_access` still transparently support `gs://` paths if you repoint the constants — most I/O helpers (`load_csv`, `save_csv`, `save_gzip`, `read_gzip_or_parts`) branch on this. There are also `*_local` duplicate variants of several path functions (e.g. `generate_file_path_local`) that are partially redundant with the now-local defaults — check which one a caller actually uses before editing path logic.

### 3. Classic ML (`scripts/model/`)

`supervised_ML.py` → `scripts/model/modeling.py::train_all_models` trains LR/RF/GBM/NaiveBayes per phenotype over the pivoted feature tables, with per-model-family imputation strategy (`load_and_filter_train`/`load_and_filter_val` handle missingness, `scripts/model/feature_utils.py` handles one-hot encoding, race harmonization, numeric coercion) and optional L1/coefficient-based feature reduction. `scripts/model/evaluate.py::evaluate_all` scores against the golden test split; `scripts/model/reporting.py` aggregates per-phenotype CSVs into overall summaries under `data/models/`.

### 4. LLM evaluation (`scripts/llm/`)

This is the largest and most complex part of the codebase (`llm_module.py` is ~4300 lines):
- **Chunking** (`TextChunker` in `llm_module.py`) — `none`/`document`/`naive`/`semantic` strategies for splitting long discharge summaries before prompting.
- **Prompting** — `PromptEngineering` assembles prompts from templates in `scripts/constants.py` (`PROMPT_ZERO_SHOT`, `PROMPT_FEW_SHOT`, `PROMPT_COT`, and per-phenotype `PROMPT_ETP_*` "Extract-Then-Phenotype" templates that ask for structured sub-element JSON, not just a status bit).
- **Calling models** — `LLMParser` dispatches to OpenRouter / Nebius / DeepInfra / Lambda depending on model family (see `MODELS`, `MODELS_OPENBIO`, `MODELS_REASONING` in `scripts/constants.py`); `scripts/llm/entropy_async.py::AsyncLLMParser` is the async counterpart used for consistency (`--run_entropy`) runs.
- **Aggregation** — chunk-level predictions roll up to discharge-summary level via `any`/`majority`/`etp`-specific logic (`ResultAggregator`).
- **Evaluation & error analysis** — `Evaluator`, `analyze_misclassification_errors`, `filter_incomplete_parsing`, `aggregate_error_csvs` in `llm_module.py`, plus `scripts/llm/reasoning_metrics.py` for confidence/reasoning-path analysis on `COT_reasoning`/`SCOT`/`TOT`/`GOT` strategies.
- `scripts/llm/llm_comprehensive_evaluation.py` is the orchestration layer `llm_evaluation.py` calls into (`llm_phenotyping_async`, `entropy_evaluation_async`); it cross-products `phenotypes × models × chunking_methods × prompt_strategies × aggregation_methods` and writes to the `output/classic/...` tree described in `llm_evaluation_README.md`.

Toy/debug constant sets (`MODELS_TOY`, `PHENOTYPES_DEBUG`, `CHUNKING_METHODS_TOY`, etc. in `scripts/constants.py`) exist specifically for fast local iteration — reach for these instead of full-scale config combinations when testing changes to the LLM pipeline.

### Path/naming conventions to know before touching preprocessing code

- `df_type` strings (`'DIAG'`, `'PROC'`, `'MEDS'`, `'CHART'`, `'LABS'`, `'RADNOTES'`, `'DSNOTES'`, `'BASELINE'`) are the vocabulary used throughout `scripts/utils.py` path builders and `mimic_parser.py --debug_type` — they don't correspond 1:1 to MIMIC-IV table names.
- `noisy_label` = silver labels (rule-based, training only); the golden/human-adjudicated labels are a completely separate file (`golden_labels.csv`) and code path, never called "noisy".
- `use_shared_paths=True` routes to `COHORT_SHARED_TEST_VAL_*` paths — these hold data that isn't phenotype-specific (the same discharge summaries are shared across all 16 phenotype test/val evaluations), so don't assume every path helper takes a meaningful `phenotype` argument.
